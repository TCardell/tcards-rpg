# SCE development instructions

Read README.md and docs/API.md before modifying. The engine/ directory is reusable and must not contain quiz-specific content or MBTI logic. New experiences should supply a set object and their own app shell, not fork core unless extending it deliberately. Keep stable action IDs left/right/farLeft/farRight/up/down and schema version 1. Do not confuse 4 intensities with four directions. Do not add arbitrary choices to the card interaction. Keep equivalent buttons for every enabled action. Preserve keyboard, touch, reduced-motion and cancel behavior. Use textContent for user content and img for SVG, never innerHTML. Avoid external dependencies. Do not alter programs/type16 or TC-HQ shell. Test state transitions and disabled actions; run node tests/model.test.cjs; verify browser checklist manually. Document changes and actual test coverage.
